# 0.1.8.1: panel identity from the discovery MAC

**Requires [elke27 0.3.13](https://pypi.org/project/elke27/0.3.13/)** (adds unicast panel discovery). No delete and re-add is needed when upgrading from 0.1.8.

## What changes
- **Panel MAC stored on the entry (#60).** Setup from discovery stores the panel's MAC (12 uppercase hex). Manual setup sends a discovery request straight to the panel's address to get it, and setup continues without it if the panel doesn't reply.
- **Check after each connect.** In the background, the integration asks the panel for its MAC. If it differs from the stored one, a WARNING is logged and the Repairs issue **"Different panel at this address"** is raised; the existing identity is kept. A match clears the issue. No reply changes nothing.
- **New entries:** the MAC is the config entry's unique ID, so adding the same panel twice is refused (*already configured*). Entity IDs for new entries may differ from those of an entry created on 0.1.8.
- **Existing 0.1.8 entries:** on the first connect, the MAC and the entry's unique ID are filled in place. No re-add. Entity and device IDs stay as they are (based on the entry ID). If another entry already uses that MAC (as its unique ID or stored MAC), the fill is skipped and the Repairs issue *Duplicate panel configuration* is raised.
- **Re-link** asks the panel at the stored address for its MAC and refuses a different panel; if the panel doesn't answer, the stored MAC is used for the check. Re-link can also fill a missing MAC, with the same duplicate refusal.
- **Address change (#59):** if the entry's unique ID is the panel MAC (the case for panels on current firmware, which report a placeholder serial), run Manual setup at the new address; the existing entry's address is updated in place and setup ends with *already configured*. If the MAC isn't known, the entry is identified by a real panel serial, or the panel doesn't answer discovery at the new address, delete and re-add. Re-link still reuses the stored host.
- **Diagnostics** now include the entry's unique ID, the stored panel MAC (`panel_mac`) and whether it was filled after setup (`panel_mac_filled`).

## Upgrade
Update the custom repository in HACS and restart Home Assistant.
