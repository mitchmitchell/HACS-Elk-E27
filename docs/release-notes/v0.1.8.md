## What's Changed

### Arm automatic: no redundant second arm (#49, fixes #43)

- If two `elke27.alarm_arm_automatic` calls for the same area run back to back, the second one
  no longer sends a second arm command when the panel's status hasn't caught up yet.
- The integration remembers an arm it just completed. A queued call treats the area as
  already armed and skips bypass, arm and rollback. A disarm clears this.
- Why it matters: a redundant arm is usually harmless, but if the panel refused it, the second
  call could undo bypasses the armed area depends on.
- Unchanged: disarm still wins over automatic arming in progress, rollback happens only on a
  definitive refusal, and panel refusals are never retried.

### Batch B: setup errors, re-linking and validation (#48) <!-- pending merge -->

- **Setup errors:**
  - Bad credentials or an invalid link at setup now stop setup and show a **re-link
    (reauthentication) prompt**.
  - Temporary problems (connection, timeout, panel errors during the first refresh) now
    **retry setup** automatically.
- **Re-link prompt from the reconnect loop:** if the panel rejects the link keys while
  reconnecting, Home Assistant now shows the re-link prompt instead of stopping silently.
- **Re-link flow:**
  - It uses Home Assistant's standard reauthentication step.
  - It keeps the panel's identity and address.
  - It refuses to re-link the entry to a different panel ("wrong panel").
  - Wrong credentials now show *invalid authentication* instead of *cannot connect*.
- **Codes:** non-numeric codes are rejected with a clear validation error, both on the alarm
  panel and in `elke27.alarm_arm_automatic` / `elke27.zone_bypass`.
- **Reliability:**
  - Full and per-area/device refreshes no longer overlap.
  - A dropped connection stops a refresh cleanly, and the refresh on reconnect runs once.
  - Narrower error handling, so cancellations aren't swallowed.
- Setup screens: labels and errors moved to translations.

### Breaking changes (#48) and what to do

No changes to entity IDs, unique IDs, device identifiers or config entry data.

1. **Non-numeric `code` is rejected by `elke27.alarm_arm_automatic` and `elke27.zone_bypass`.**
   - What happens: the call fails validation before anything is sent to the panel.
   - What to do:
     1. Open each automation or script that calls these actions.
     2. Make sure `code` is digits only (for example `"1234"` or `!secret elk_alarm_code`, where
        the secret is digits only).
     3. Run the automation once and check the trace.
2. **Re-link step renamed** (`relink` → `reauth_confirm`).
   - What happens: only a re-link prompt that's open during the upgrade is affected.
   - What to do: if a re-link prompt was open when you upgraded, dismiss it, reload the
     integration (**Settings → Devices & services → Elk E27 Alarm Engine Integration → ⋮ →
     Reload**) and open the new prompt.
3. **Setup failures behave differently.**
   - Bad credentials or an invalid link now show a setup error plus a re-link prompt (before:
     endless retry or a raw error).
   - Library errors during the first refresh now retry setup (before: a setup error).
   - What to do:
     1. If the integration shows a re-link prompt after upgrading, open it and enter the
        access code and passphrase from your installer.
     2. If it shows "retrying setup", check that the panel is powered and reachable. It will
        connect by itself once it is.
