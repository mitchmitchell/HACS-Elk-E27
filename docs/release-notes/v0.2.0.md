> [!WARNING]
> **0.2.0 needs a one-time delete and re-add.** Entity names change; entity IDs are normally
> kept. Check automations, scripts and dashboards that rely on names. Entries created before
> 0.2.0 fail setup with: "This entry was created before the integration ID existed, or its ID
> is invalid. Delete the integration and add it again." Follow
> [Upgrading to 0.2.0](../../README.md#to-020).

## Breaking changes
1. **Delete and re-add required** from any 0.1.x. Each install gets its own random 12-digit
   integration ID, sent to the panel, and the device layout changed. There is no automatic
   migration and no Repairs issue; old entries fail setup with the message above.
2. **Areas are devices:** each area the panel reports gets a device named after it; its alarm
   panel is named after the area and its zones sit under it. Zones with no area and panel-wide
   entities stay on the panel device. Entity names change (for example "<panel> <area>" becomes
   "<area>", and "<panel> <zone>" becomes "<area> <zone>"). Entity IDs are normally kept after
   the delete and re-add; new area-based IDs such as `alarm_control_panel.<area>` apply only to
   fresh installs, where identical names get `_2` IDs. Check automations, scripts and
   dashboards that rely on names. Zone names are used as the panel reports them, so
   "Garage Garage door" can appear.
   <!-- PENDING MITCH: E2 Q2/Q3 defaults -->
3. **New integration ID per install:** the panel's Network Devices list shows a new 12-digit
   entry. <!-- PENDING MITCH: tell users to remove the old 0.1.x entry -->
4. **Diagnostics changed:** new connection, reconnect, out-of-date-status, version and area
   device fields; `integration_serial` removed. Host, panel MAC, unique ID and integration
   ID are redacted; link keys are never included.
5. **Setup errors** are reported through Home Assistant's first refresh: the same retry or
   re-link outcome, different log text. Reconnect log lines move from logger `elke27.hub`
   to `elke27.coordinator`; update log filters.
6. **Availability:** on connection loss all entities go unavailable together and recover
   together on reconnect.
7. **Out-of-date status** is shown in diagnostics only; status out of date for more than
   60 s while connected is read again once automatically (never a command).
8. **Internal:** `custom_components.elke27.hub` is removed; scripts or tests importing it break.
9. **Requires elke27 0.3.14** (was 0.3.13).

## Changed
- After arming, disarming or bypassing, the integration uses the status the library already
  refreshed, saving a round trip. If that refresh didn't work it reads the status once more;
  each command is still sent only once.
- Reconnect, Repairs and re-link work as in 0.1.x: retries back off up to about 5 minutes;
  a Repairs issue appears only after 3 consecutive non-network failures (a plain network
  outage leaves entities unavailable without one); a rejected link asks you to re-link.
- Area devices the panel no longer reports are removed at the next setup, or you can
  delete them from the device page.
- Downgrading to 0.1.x also needs a delete and re-add.
